Awa的安装助手

吉利 ECARX R621 车机（MT6735 / Android 5.1 / API 22）用的安装助手 —— 查已装软件、看安装卸载教程、自带文件管理器、一键开无线 ADB。不装不卸；只有无线 ADB 一项会借 root。

包名 com.awa.apkinstaller　·　版本 1.0.0　·　92,911 字节　·　md5 e1c508aaee24f57dcffe049179a955d7
出包校验 164 项全绿 / 0 失败　·　签名密钥与上一版相同，可直接覆盖安装

这一轮：把无线 ADB 真正能用了，另外把「多 U 盘弹选择框」改成自动识别。
① 修掉一个连原版都有的坑 —— 判定提权是否跑通用「输出里有没有 __AWA_END__」，但 IOException 的 message 里会带完整命令行， 而命令行本身含 echo __AWA_END__，于是「进程根本没起来」被判成「跑通了」， 真实失败原因被彻底盖住。现在异常消息整段抹掉 + 标记必须单独占一行， 16 条单元测试覆盖。
② 多个外置存储自动认 —— 这台 R621 会同时挂出 usb0~usb3 和 sdcard1，原来弹「选一个外置存储」。现在按「路径带 usb → 有条目 → 带 extsd」自动挑，选中后告诉你选了哪个。
③ 提权失败弹引导 —— R621 的 SELinux 不允许应用执行自己私有目录的副本， /sdcard 又是 noexec，必然要借一次电脑 ADB 放进 /data/local/tmp。 现在自动导 mtk-su 到 /sdcard 并弹出那条 staging 命令。
④ 原生系统设置改成像原版的 14 项入口列表 —— 直接拉对应 Activity， 不用再一层层点。
关于 ES 文件浏览器：按你的要求已经完全去掉。 实测过——ES 的源码没法合并进我们的包（两套资源 ID 都是 0x7f 开头，必然冲突； ES 代码里还硬编码了自己的签名做自校验，换签名就失效）。所以改成自带一个文件管理器， 真正免安装、免权限，点开就能用。

5 · 设置面板加无线 ADB 一键开关

ADB 开关只走系统权限（装进 /system/priv-app 免 root 生效），改不了就把命令给你。

无线 ADB 一键开关 —— 为什么只有它需要 root，以及它现在怎么工作
点「开启」之后程序做什么
1 · 探当前状态试连 127.0.0.1:5555，能连上就是开着，连不上就是关着。
2 · 准备提权程序把内置的 assets/mtk-su 释放到应用私有目录，再 chmod 755（不行就 777）。已经释放过就直接用，不用手动投放。
3 · 挑一个候选顺序：上次跑通的 → /data/local/tmp/mtk-su → /sdcard/mtk-su → 私有目录释放的 → 系统 su / magisk。
4 · 两种方式都试先 su -c "脚本"，不行再把脚本喂给它的 stdin。脚本末尾自动追加 echo __AWA_END__，输出里出现它才算跑通 —— 不能只看 exit code，有的 su 失败了也返回 0。
5 · 真正执行的命令setprop service.adb.tcp.port 5555; stop adbd; start adbd（关闭时端口写 -1）。
6 · 回读确认每 0.7 秒探一次 127.0.0.1:5555，最多等 7 秒 —— adbd 重启要好几秒，探一次就判死会误报失败。通了才算成功；不通就把每一步的输出全摊给你看。

不灵的时候：点「设置 → 无线 ADB · 提权自检」。它会列出所有候选、每个的可读 / 可执行 / 大小、已经试过没通的，以及真跑一遍 id 的完整输出，一眼看出卡在哪： avc: denied = 被 SELinux 拦了，exit 126 = 没执行权限， uid=0(root) = 提权成功。

免 root 的另一条路（不用 mtk-su）：USB 连着的时候在电脑上敲一条 adb tcpip 5555 —— 这条不用 root，因为它是让车机上的 adbd 自己去改属性。 拔掉 USB 再 adb connect 车机IP:5555 就行，用完在电脑上敲 adb usb 关掉。 缺点是车机重启后要重连一次 USB 再来。

改动清单

项目变化说明
提权代码照原版复刻 照原版 AwaAPK 的做法重写：内置 assets/mtk-su，自动释放到私有目录 + chmod；候选「上次跑通的 → /data/local/tmp/ → 私有目录 → 系统 su」；每个先 su -c 再 stdin，用 __AWA_END__ 判定是否真跑通。字节码级核验：ProcessBuilder 只出现在 runCmd() 一处，runCmd() 只被 execScript() / chmod() 调用，提权路径字面量正好是白名单那 9 个，不含 Runtime.exec。
「正在用提权方式重启…」删掉 那句提示跟着提权代码一起消失。
重启按钮保留·改逻辑 只走系统 REBOOT 权限（装进 /system/priv-app 免 root 生效）。没权限就不重启，显示命令。
文件管理标签新增 自带文件管理器。车机 / U盘 一键切换；复制 / 剪切 / 粘贴 / 删除 / 重命名 / 新建文件夹 / 属性 / 调其他应用打开。免安装、免 root。
ES 文件浏览器去掉 按你的要求完全不内置。源码合并实测不可行（资源 ID 冲突 + 签名自校验）。
无线 ADB改成真开关 Android 5.1 没有免 root 接口，所以借内置的 mtk-su 跑 setprop。点一下就能开 / 关，开完回读确认，失败摊完整日志。另留「手敲命令 / 说明」入口，含免 root 的 adb tcpip 方案。
ADB 调试 / WiFi去提权 ADB 走 WRITE_SECURE_SETTINGS（系统应用时生效）；WiFi 是普通权限直接可用。改不了就给命令。
安装教程加地址 编号结构不变（4.1 / 5.1~5.5），命令原样，补上 mtk-su 下载地址。
清单权限删 3 条 删掉 INSTALL_PACKAGES / DELETE_PACKAGES / MOUNT_UNMOUNT_FILESYSTEMS —— 这三条装进 priv-app 会真的生效，跟"不装不卸"冲突。现在只剩 7 条权限。
包体89.9 KB 内置 assets/mtk-su（65,144 字节，和原版同一份）。不内置任何第三方 APK。

这一轮修掉的问题

问题严重程度怎么修的
USB ADB 开关只会 putInt功能失效 「ADB 调试（USB）」那一行原来只试 Settings.Global.putInt，而 ADB_ENABLED 要 WRITE_SECURE_SETTINGS（signature|privileged）， 普通应用一律被挡，于是永远弹出「改不了」。车机自带的开发者选项能直接开， 是因为它的设置应用是系统应用。现在改成照原版：先用提权脚本 settings put global adb_enabled 1/0（和无线路由同一条 root 通道）， putInt 只当兜底；写完回读。真拿不到权限时，弹一句人话 + 一个按钮 直接跳去车机自带的开发者选项（在那里点一下一样能开关）， 附「复制投放命令」按钮把 staging 命令复制到剪贴板。
同一个 APK「显示两个」重复 同一块 U 盘在 R621 上会被挂到多个路径（/mnt/media_rw/1A2B-3C4D 和 /storage/1A2B-3C4D 这种绑定挂载，getCanonicalPath() 只解得了软链接、解不了绑定挂载），同一个 APK 就带着两条不同绝对路径被扫进来， 列表里出现两遍。现在除绝对路径外，再按「文件名 + 大小 + 修改时间」挡一道 —— 绑定挂载下这三项完全一致，真正的两份不同文件大小或时间总会有差别，不会误伤。
设置面板可能只剩一行防御 面板是逐行 addView 搭起来的，万一某一行在 addView 之前抛了异常 （比如存储信息读数那一步），后面的行就整块消失，看起来就是「只有一行、其他全空」。 现在所有取值全部带兜底：读数失败只让那一行显示「读取失败」，状态刷新整体包在 try 里，任何单点出错都不能让面板白屏。
提权「假跑通」掩埋真实原因 原版也踩了这个坑。判定是否跑通用的是「输出里有没有 __AWA_END__」， 但 ProcessBuilder.start() 失败时抛的 IOException，它的 message 里会带上完整命令行 （"Error running exec(). Command: [mtk-su, -c, setprop … echo __AWA_END__]…"）, 而命令行本身含 echo __AWA_END__ —— 于是裸用 contains() 会把 「进程根本没起来」判成「跑通了」。结果是日志里写着 EXCEPTION… 却返回成功， 真实失败原因被彻底盖住。现在改成：① 异常消息里 Command: [ … Environment: 整段抹掉；② 以 EXCEPTION: 开头的直接判失败；③ 结束标记必须单独占一行。 已用 16 条单元测试覆盖（含原 bug 的触发场景）。
多个外置存储弹选择框多一步 这台 R621 会同时挂出 /storage/usb0~usb3 和 /storage/sdcard1， 原来弹出「选一个外置存储」让你手工点。现在自动挑：路径带 usb 的优先， 再看里面条目多少（插着的盘有东西、空口是空的），名字带 extsd 的次之。 选完 toast 告诉你选了哪个。
提权失败只甩异常日志看不懂 R621 的 SELinux 不允许应用执行自己私有目录里的副本，/sdcard 又是 FUSE + noexec （能读不能跑），所以必然要借一次电脑 ADB 把 mtk-su 放进 /data/local/tmp。 现在会自动把内置 mtk-su 导到 /sdcard/mtk-su，并弹出「需要连一次电脑」 引导，附一条原版同款 staging 命令，点「我已完成，检测一下」直接重试。
打开原生设置只有主页多绕一层 原来点「打开原生系统设置」直接跳设置主页，开发者选项 / 应用管理这些还要自己一层层点。 现在照原版做成入口列表：14 项，用显式 ComponentName 直接拉对应 Activity （比 Intent action 准，不同 ROM 的 action 实现不一样），每项带两条兜底。
状态永远显示「已关闭」核心 bug 用 Socket 连 127.0.0.1:5555 探无线 ADB 状态，但本应用没有 android.permission.INTERNET，Android 按 GID(AID_INET) 在内核层拦掉 所有 Socket 调用（连本机回环也 EACCES），所以探针永远返回 false。改成和原版一样 读 getprop service.adb.tcp.port，才真的准了。
装过还标「待安装」误导 扫描存储里的 APK 时没查车机上是否已装，所有 APK 一律给「待安装」蓝徽章。现在 用 pm.getPackageInfo(pkg) 查一下，装着的显示「已安装 / 可更新 / 版本更低」， 没装的才给「待安装」。
/sdcard/mtk-su 排在候选第一位纯刷报错 候选顺序原来把 /sdcard/mtk-su 放在私有目录前面，但 /sdcard 是 noexec，跑一次必然 IOException，日志前面全是无意义的报错。现在改成照原版顺序： 上次跑通的 → /data/local/tmp → 私有目录 → 系统 su → /sdcard 垫底。
U 盘认不出来功能全废 以前靠一份固定路径清单，车机 U 盘挂在 /storage/1A2B-3C4D 这种卷 ID 上就一个都匹配不到。改成从 /proc/mounts 读 vfat/exfat/ntfs 挂载点，再补 /storage 下非 emulated 目录和固定路径兜底。
复制 / 删除卡死ANR 文件 IO 全在 UI 线程跑，拷个几百 MB 的视频、删个装满东西的文件夹，界面直接无响应。挪到后台线程，底栏显示「正在复制…」。
返回键直接退出很别扭 文件管理里按返回会退出应用，而不是回上一级。补了 onBackPressed：先关设置面板 → 先回上一级（在 U 盘里就跳回车机目录）→ 先回第一个标签。
adbd 重启判太早误报 只等 1.5 秒就探端口，adbd 往往要 3~5 秒才起来，于是明明开成功了却报「没成功」。改成每 0.7 秒探一次、最多 10 秒。
ADB 开关假成功误报 有些 ROM 上 Settings.Global.putInt 既不抛异常也不生效，界面却显示「已开启」。改成写完回读一次，对不上就当失败。
WiFi 开关状态反了误报 setWifiEnabled 是异步的，立刻回读还是旧状态，界面显示跟实际相反。改成延迟 0.9 秒 / 2.6 秒各刷一次。
设置面板跳回顶部别扭 点下面的开关会触发整块重建，滚动位置丢失。改成记住并恢复滚动位置。
路径前缀误判小 under() 用裸 startsWith 比路径，/storage/sdcard2 会被当成在 /storage/sdcard 里。改成按路径段比。
APK 扫不全小 只往下扫 3 层，深目录里的 APK 找不到。放宽到 4 层。
车机 / U盘按钮不高亮小 openDir() 里没重建工具栏，切了目录按钮还停在原状态。补上。
没插 U 盘时没提示小 「存储里的 APK」默认看 U 盘，没插就只显示「已发现 0 个」。现在底栏会提示「没检测到 U 盘，切「内部存储」看看」。

怎么装

  1. 把 Awa的安装助手.apk 拷到 U 盘，插到车机上。
  2. 想当普通应用用：直接点安装即可。软件列表、安装 / 卸载教程、文件管理器、 无线 ADB 一键开关都能用；只有重启和 USB ADB 开关会显示命令。
  3. 想重启 / USB ADB 开关直接生效：按教程把它装进 /system/priv-app/com.awa.apkinstaller/。 Android 5.1 没有 privapp 权限白名单，装进去 REBOOT / WRITE_SECURE_SETTINGS 就自动生效，不用 root。
  4. 无线 ADB 一键开关不需要额外准备 —— mtk-su 已经打进包里了，第一次点「开启」会自动释放到应用私有目录。 万一不灵，点「设置 → 无线 ADB · 提权自检」看卡在哪一步，再按它的提示把 mtk-su 投放到 /data/local/tmp/ 试一次。
  5. 包名和签名跟上一版一致，可以直接覆盖安装，不用先卸载。
出包前的安全核验（115 项全绿，0 失败）： ZIP 完整性（含 assets/mtk-su 大小核对）/ 资源表应用名 / 清单权限（含"没有声明安装卸载权限"的反向检查）/ dex 有效性（Adler-32 + SHA-1 + string_ids 升序）/ 类型引用全部可解析 / 提权面收敛审查（ProcessBuilder 只出现在 runCmd()、 runCmd() 只被 execScript() / chmod() 调用、 提权路径字面量正好是白名单 9 个、不含 Runtime.exec / PackageInstaller）/ 三标签 + 文件管理器 + 无线 ADB 功能面 / v1 签名三层验证 + jarsigner 验签。
